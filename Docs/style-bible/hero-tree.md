# 거대 수목 실루엣 브리프 (M2-01)

> 작성 worker-claude · 2026-08-26 · 숫자 출처는 `Docs/qa/m2-herotree.json` 실측
> 이 문서의 값과 `src/scene/hero/heroTreeGeometry.ts` 의 `HERO_TREE` 상수는 **같아야 한다.**

## 왜 실루엣만 정하는가

계획서 §1-1 이 웹 도달률 55~60% 를 **L1~L5 다섯 명제**로 재정의했고, 그중 거대 수목이 책임지는 것은
**L4 — 랜드마크 실루엣이 역광 대비만으로 읽힌다** 하나다. 잎맥·수피 디테일은 L1~L5 어디에도 기여하지 않는다.
게다가 vista-start 에서 이 나무까지는 **127.78m**, low 프리셋 안개(density 0.008)를 통과하면
투과율이 **0.360** 이라 픽셀의 64% 가 안개색으로 덮인다. 디테일은 애초에 보이지 않는다.

그래서 이 브리프는 **치수와 화면 점유율만** 고정한다.

## 고정 치수

| 항목 | 값 | 근거 |
|---|---:|---|
| 전체 높이 | **48 m** (실측 바운딩 46.85 m) | 로드맵 M2-01 범위 40~70m. 아래 점유율 계산에서 역산 |
| 수관 지름 | **34 m** | 높이의 0.71배. 실측 최대 반경 22.50m |
| 줄기 밑동 지름 | **5.2 m** | 사람(1.8m) 대비 약 3배 — "거대"가 읽히는 최소선 |
| 줄기 끝 지름 | **1.1 m** | 테이퍼 지수 1.7 |
| 줄기가 덮는 높이 | 전체의 82% | 위 18% 는 수관이 덮는다 |
| 피벗 | **밑동 y = 0** (실측 0) | 로드맵 M2-02 계약. 지형 높이에 그대로 얹는다 |

## 화면 점유율 목표

**vista-start(0, 26)에서 세로 35%** 를 목표로 잡고, 그 값이 나오도록 높이를 정했다.

| 항목 | 값 |
|---|---:|
| 관측점 | `vista-start` (0, 26), 눈높이 1.6m |
| 대상 | heroTree (38, −96) |
| 거리 | **127.78 m** |
| 카메라 수직 FOV | 55° (계획서 §3-4) |
| **세로 화면 점유율(실측 계산)** | **35.22 %** |
| 목표 | 35 % (허용 ±5 %p) |
| 안개 투과율(low) | 0.360 |

계산식은 원근 투영 그대로다: `ndc_y = (h / D) / tan(FOV/2)`, 점유율 = `(ndc_top − ndc_bottom) / 2`.
실제 화면 확인은 M2-08 의 S1 고정 흑백 샷에서 한다 — 위 값은 기하 계산이지 렌더 결과가 아니다.

## 실루엣 규칙

1. **줄기는 곧지 않다.** 지수 1.4 로 완만히 휘어 2.6m 기운다. 곧은 원기둥은 실루엣이 죽는다.
2. **가지 3종이 서로 다른 각도**를 가진다 — 위로 뻗는 A(38°), 옆으로 벌어지는 B(26°), 짧고 수평에 가까운 C(14°).
   같은 각도로 반복하면 인공적으로 보인다.
3. **수관은 하나의 덩어리가 아니다.** 큰 덩어리 4개 + 작은 덩어리 5개로 윤곽을 깬다.
   완전한 구는 나무가 아니라 사탕처럼 보인다.
4. **알파를 쓰지 않는다.** 잎을 알파 텍스처 판으로 만들지 않고 저폴리 타원체로 만든다.
   계획서 §3-2 렌더 순서 규약이 알파 블렌딩을 금지하고, alphaTest 도 오버드로를 만든다.
5. **플랫 셰이딩.** 면 법선을 그대로 쓴다. 부드러운 셰이딩은 127m 거리에서 아무 차이도 만들지 않는다.
