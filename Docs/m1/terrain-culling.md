# M1-25 지형 청크 프러스텀 컬링 실측

측정 2026-08-26 KST · 순수 계산(three 수학 클래스, GPU 불필요)

## 구성
- `src/scene/Terrain.tsx`: 250m 를 **4×4 = 16 청크**로 나눈다. 청크당 64×64 세그먼트.
- 청크마다 별도 `<mesh>` 이고 `geometry.computeBoundingSphere()` 를 호출한다.
- three 는 `Object3D.frustumCulled` 가 기본 true 이고 바운딩 스피어가 있으면 프러스텀 밖 객체를 draw 하지 않는다.
  즉 컬링을 켜는 별도 코드가 필요한 것이 아니라, **바운딩 스피어가 있는 청크로 쪼갠 것 자체가 컬링 단위를 만든 것**이다.

## 카메라 (계획서 §3-4 FollowCamera 값)
- FOV 55° · aspect 1.7778 (1280×720 low) · near 0.1 · far 400
- 플레이어 뒤 6m · 위 2.2m · pitch -12°

## 판정: PASS — 보이는 청크만 draw 된다

- 최소 2개 / 최대 14개 / 평균 7.40개
- 즉 지형 드로우콜이 항상 16 이 아니라 **2~14** 범위로 줄어든다.
- 청크로 쪼개지 않았다면(한 장 메시) 지형은 항상 1 드로우콜이지만 **화면 밖 삼각형까지 전부 제출**된다.
  16 청크 중 평균 7.40개만 그리므로 제출 삼각형이 약 54% 줄어든다.

## 교차 근거
- 통합 헤드리스 실측(`Docs/m1/integration-smoke.json`) 최대 드로우콜 **59** — 계획서 §4-1 예산 200 이내.
- 지형 16 + 길 1 + 큐브 4 + 그리드 1 + 식생 3 + 바위 3 + 플레이어 1 = 29 가 전부 그려질 때의 하한이고,
  그림자 패스가 캐스터를 한 번 더 그리므로 59 는 컬링이 동작하는 상태와 모순되지 않는다.

# M1-24 종별 최대 표시 거리 실측

측정 2026-08-26 KST · 순수 계산. 산포는 컴포넌트와 같은 seed·같은 reject 로 재현했다.

## 적용 값 (low 프리셋)

| 종 | 최대 표시 거리 | 출처 |
|---|---:|---|
| 풀·꽃·관목(식생 3종) | 25 m | `quality-presets.json` low.grassInstances.radius (계획서 §3-6) |
| 바위 3종 | 80 m | `quality-presets.json` low.rockDrawDistance — **M1-24 에서 신설**. low 그림자 거리(80m)와 맞췄다 |

## 구현

`InstancedMesh.count` 를 카메라 거리 안쪽 개수로 낮춘다. count 뒤의 instance 는 GPU 에 제출되지 않으므로
"카메라 거리 밖 instance 표시 0" 이 성립한다. 카메라가 2m 이상 움직였을 때만 다시 채워 매 프레임 행렬 쓰기를 피한다.
지형 높이는 좌표가 고정이라 산포 시점에 한 번만 구해 둔다(갱신마다 heightmap 을 다시 타면 그게 스톨이 된다).

## 벤치 동선 키프레임에서 실제로 그려지는 instance 수

| t(초) | 카메라 (x, z) | 식생 표시/전체 | 바위 표시/전체 |
|---:|---|---:|---:|
| 0 | (4.9, 27.2) | 1856 / 6000 | 98 / 300 |
| 15 | (-8.5, -14.2) | 2916 / 6000 | 94 / 300 |
| 30 | (11.4, -53.7) | 0 / 6000 | 79 / 300 |
| 45 | (35.1, -90.9) | 0 / 6000 | 63 / 300 |
| 60 | (40.0, -101.5) | 0 / 6000 | 60 / 300 |

- 식생 전체 6000개 중 어느 지점에서도 최대 2916개만 그려진다.
- 바위 전체 300개 중 최대 98개만 그려진다.
- 거리 밖 instance 는 `mesh.count` 밖이라 **표시 0** 이다.

## ★ 함께 드러난 사실 (고치지 않고 보고)

`Foliage.tsx` 의 산포는 **월드 원점 중심 반경 25m 원반**이다(`halfExtent: radius` + `hypot(x,z) > radius` 거부).
계획서 §3-2 는 풀을 "카메라 반경 내만" 으로 적었는데 구현은 원점 기준이다. 그래서 플레이어가 길을 따라
멀어지면 식생 표시 수가 0 이 된다(위 표 t=30 이후). M1-24 의 완료 조건 자체는 만족하지만,
길 주변에 식생이 없는 상태다. 카메라 추종 산포로 바꾸는 것은 `Foliage.tsx` 소유자(worker-codex) 와
밀도 설계를 다시 잡아야 하는 일이라 이번에 건드리지 않았다.
