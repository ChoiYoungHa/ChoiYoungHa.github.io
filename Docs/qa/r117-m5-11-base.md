## 2. 기본 프리셋 `base` 승격 + 자동 후퇴

- `useRuntime.ts`: `DEFAULT_QUALITY_PRESET = 'base'`, 초기 `preset` 을 그 값으로. `parseQualityPreset` 은 `?q=low|base` 를 항상 우선하고 지정이 없을 때만 기본값을 쓴다.
- `src/systems/perf/autoFallback.ts`(순수, 96줄): 워밍업 `WARMUP_SECONDS 3` 을 버리고 `WINDOW_SECONDS 8` 구간의 프레임 간격만 모아 평균 fps·하위 1% fps 를 낸다. 하위 1% 정의는 `systems/perf.ts` 와 **같은 식**(가장 느린 1% 프레임의 평균 프레임타임의 역수). 관문(평균 30 / 하위1% 20) 미달이면 `low` 로 **1회만** 내리고 이후 판정하지 않는다.
  - 워밍업을 버리는 이유: 첫 수 초는 셰이더 컴파일·텍스처 업로드 구간이라 그대로 재면 어떤 기기에서도 후퇴가 발동한다(계획서 §4-3 이 측정에 워밍업 30초를 두는 것과 같은 이유).
- 훅은 1곳: `RuntimeHud.tsx` 의 기존 `useFrame`(이미 dt 를 집계하던 자리). 활성 조건은 `isAutoFallbackEligible(location.search, window.__benchMode)` — **`?q` 명시 시 비활성**(사용자 우선), **`?route=bench|final` 측정 중 비활성**(정본 불변). 후퇴는 현재 preset 이 `base` 일 때만 적용한다.
- `Settings.tsx`: 후퇴가 실제로 일어난 경우에만 "성능 관문 미달로 base → low 자동 전환됨" 1줄(`data-testid="settings-auto-fallback"`). 사용자가 select 로 되돌릴 수 있다.
- 테스트 `test-auto-fallback.mjs` **12/12**: 워밍업 무판정·워밍업 느린 프레임 제외·평균 미달 후퇴·평균은 통과해도 1%low 미달이면 후퇴·1회성·창 종료 전 무판정·dt 이상값 무시·표본 0 무후퇴·perf.ts 와 동일 정의·경계값(정확히 30/20 은 통과)·`?q` 우선·bench/final 비활성.
- 측정 러너는 모두 URL 에 `q=low` 를 명시한다(`run-bench.mjs --preset` 기본 low, `game-walk.mjs`, `lookdev-variants.mjs`, `cdp-shot.mjs`, `url-smoke.mjs`) → **측정 정본 불변**.

## 4. 잔존

1. **pipelines 59(기본 경로) / 70(게임 중) > 48**, **base 1%low 17.31 < 20**, 사냥 중 avg 135.8→89.5 — 모두 원본 GLB(메시 7·스킨 7·텍스처 5장·15MB)가 원인. R118 최적화본 도착 시 같은 절차(bench low/base 1회 + pipelines 프로브 + final)로 재측정해야 한다.
2. `char_player.glb` 는 `loading-manifest.json` 에 없어 `check-payload` 총계(13.35MB)에 잡히지 않는다. 실제로는 15MB 를 런타임에 받는다 — manifest 등록 여부는 master 결정.
3. 로드맵 M5-11 은 tris 조건 미충족으로 미체크.
4. 발 미끄러짐 육안은 연속 프레임 확인이 남았다(정지 캡처 3장으로는 자세 전환까지만 확인).
